# RAG Module

Основные возможности:

- Извлечение и обработка текста из PDF-документов.
- Разбиение документов на фрагменты.
- Создание векторных представлений и сохранение их в Qdrant.
- Поиск релевантных фрагментов по пользовательскому запросу.
- Дополнительная оценка релевантности найденных фрагментов (reranking).
- Генерация ответов в структурированном JSON-формате.
- Проверка соответствия цитат исходным фрагментам документов.
- Проверка пользовательских сообщений на наличие потенциально опасных симптомов.
- Генерация последовательных уточняющих вопросов на основе предыдущих ответов пользователя.
- Извлечение симптомов и дополнительной информации из ответов пользователя.
- Валидация извлечённых симптомов.
- Формирование итоговых рекомендаций на основе ответов пользователя и найденных медицинских документов.

## Требования

- Python 3.12+
- Запущенный Qdrant.
- Доступ к GigaChat API.
- Docker Desktop (для запуска Qdrant через Docker).
- Доступ к Hugging Face для первоначальной загрузки моделей эмбеддингов и reranker.

## Настройка

### 1. Создание виртуального окружения

В корне проекта выполните:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Установите библиотеку и её зависимости:

```powershell
python -m pip install -r requirements.txt
```

### 2. Настройка переменных окружения

Создайте файл `.env` на основе шаблона:

```powershell
Copy-Item .env.example .env
```

Откройте `.env` и укажите настройки:

```env
GIGACHAT_CREDENTIALS=ваши_учетные_данные
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat-2

QDRANT_URL=http://localhost:6333
COLLECTION_NAME=medical_documents
VECTOR_SIZE=384
```

`GIGACHAT_CREDENTIALS` необходимо заполнить действующими учетными данными GigaChat.

Не публикуйте файл `.env` и не добавляйте его в Git.

### 3. Запуск Qdrant

Запустите Docker Desktop.

В PowerShell выполните:

```powershell
docker run -d --name qdrant `
  -p 6333:6333 `
  -v qdrant_storage:/qdrant/storage `
  qdrant/qdrant
```

Проверьте доступность Qdrant:

```powershell
Invoke-RestMethod http://localhost:6333
```

Если контейнер Qdrant уже существует, повторно создавать его не нужно. Для запуска используйте:

```powershell
docker start qdrant
```

При запуске Python внутри Docker-сети вместо `localhost` укажите адрес Qdrant в этой сети, например:

```env
QDRANT_URL=http://qdrant:6333
```

### 4. Подготовка документов

В корне проекта создайте папку `documents`:

```powershell
New-Item -ItemType Directory -Force documents
```

Поместите в неё PDF-файлы.

Поддерживаются PDF с текстовым слоем. Для сканированных документов без распознаваемого текста потребуется предварительное OCR.

### 5. Проверка установки

Проверьте импорт публичных функций библиотеки:

```powershell
python -c "from rag_module import search, ask, index_document, generate_next_question, generate_recommendation, process_patient_answers; print('RAG Module успешно установлен')"
```

Если команда выполнилась без ошибок, импорт библиотеки выполнен успешно.

При первом использовании моделей эмбеддингов или reranker может потребоваться их загрузка с Hugging Face. Это может занять некоторое время.

## Использование библиотеки

### 1. Индексация документов

Для добавления PDF-документа в базу знаний используется функция `index_document()`.

```python
from rag_module import index_document

result = index_document("documents/medical_document.pdf")
print(result)
```

Функция выполняет обработку документа и добавляет его фрагменты в Qdrant.

Каждый новый документ необходимо индексировать отдельно. Повторный запуск приложения сам по себе не запускает индексацию.

### 2. Поиск информации

Для поиска релевантных фрагментов документов используется функция `search()`.

```python
from rag_module import search

results = search(
    question="Какие причины могут вызывать боль в пояснице?",
    limit=5
)

for item in results:
    print(item)
```

Параметры:

- `question` — поисковый запрос.
- `limit` — максимальное количество возвращаемых фрагментов.

Функция возвращает список найденных фрагментов с информацией об источниках.

### 3. Генерация ответа

Для получения ответа на основе найденных документов используется функция `ask()`.

```python
from rag_module import ask

result = ask(
    question="Какие причины могут вызывать боль в пояснице?",
    limit=5
)

print(result)
```

Функция выполняет поиск в Qdrant, передаёт найденные фрагменты в GigaChat и возвращает структурированный результат.

Ответ содержит:

- `claims` — список утверждений, сформированных на основе найденных документов.
- `evidence` — подтверждающие цитаты и сведения об источниках для каждого утверждения.
- `insufficient_information` — сообщение о недостаточности информации, если найденных данных не хватает для ответа.

Если релевантные документы отсутствуют или информации недостаточно, библиотека может вернуть пустой список утверждений.

### 4. Проверка безопасности сообщений

Для проверки пользовательского сообщения на наличие потенциально опасных симптомов используется функция `check_message_safety()`.

```python
from rag_module.triage.message_safety_checker import check_message_safety

result = check_message_safety(
    "У меня сейчас сильная давящая боль в груди, тяжело дышать."
)

print(result.model_dump())
```

Проверка выполняется в несколько этапов:

1. Сообщение анализируется независимыми правилами обнаружения опасных признаков.
2. Если правило обнаруживает опасный признак, проверка немедленно возвращает соответствующий результат.
3. Если правила не обнаружили опасный признак, сообщение дополнительно анализируется с помощью GigaChat.
4. Результат проверяется по Pydantic-модели.
5. При ошибках обработки или недостаточной определённости используется безопасный вариант результата с остановкой опроса.

Основные значения `danger_status`:

- `dangerous` — обнаружен потенциально опасный признак.
- `uncertain` — информации недостаточно, требуется дополнительная оценка.
- `no_critical_signs_detected` — в сообщении не обнаружены предусмотренные проверкой критические признаки.

Дополнительно результат содержит:

- `urgency` — оценка срочности.
- `reason` — причина принятого решения.
- `matched_signs` — обнаруженные признаки.
- `recommended_action` — рекомендуемое действие.
- `should_stop` — необходимость остановить обычный опрос.

При значении `dangerous` опрос прекращается и пользователю рекомендуется вызвать скорую помощь по номеру 103 или 112.

При значении `uncertain` обычный опрос также прекращается до дополнительного уточнения ситуации.

**Важно:** `no_critical_signs_detected` не означает, что пользователь здоров или что медицинский риск отсутствует. Проверка предназначена для предварительного обнаружения отдельных опасных признаков и не заменяет медицинскую оценку.

### 5. Генерация уточняющих вопросов

Для проведения последовательного опроса пользователя используется функция `generate_next_question()`.

```python
from rag_module import generate_next_question

answers = [
    {
        "question": "Что вас беспокоит?",
        "answer": "Болит поясница"
    },
    {
        "question": "Когда появилась боль?",
        "answer": "Три дня назад"
    }
]

result = generate_next_question(answers)

print(result)
```

Функция принимает предыдущие вопросы и ответы пользователя и генерирует один следующий уточняющий вопрос с помощью GigaChat.

Результат содержит поле:

- `question` — следующий вопрос пользователю.

Генерация уточняющих вопросов выполняется напрямую через GigaChat и не использует RAG или Qdrant.

Перед генерацией вопроса сообщения пользователя проходят проверку безопасности.

### 6. Извлечение и валидация симптомов

После завершения опроса библиотека извлекает из ответов пользователя информацию о симптомах.

Для этого используется функция `extract_symptoms()`.

```python
from rag_module.triage.symptom_extractor import extract_symptoms

answers = [
    {
        "question": "Что вас беспокоит?",
        "answer": "Три дня насморк и першение в горле."
    },
    {
        "question": "Есть ли хронические заболевания?",
        "answer": "Нет."
    }
]

symptoms = extract_symptoms(answers)

print(symptoms)
```

GigaChat анализирует историю ответов и формирует структурированное представление симптомов.

Для каждого симптома могут извлекаться:

- `name` — название симптома.
- `status` — наличие или отсутствие симптома.
- `time` — временная характеристика.
- `subject` — субъект, к которому относится симптом.
- `severity` — выраженность симптома.
- `onset` — время появления.
- `frequency` — частота проявления.
- `details` — дополнительные сведения.

Результат дополнительно проверяется функцией `validate_symptom_extraction()`.

```python
from rag_module.triage.symptom_validator import validate_symptom_extraction

validation = validate_symptom_extraction(symptoms)

print(validation.model_dump())
```

Валидатор проверяет структуру данных, наличие обязательных полей, дублирование симптомов, противоречия и неопределённость извлечённой информации.

Основные поля результата:

- `is_valid` — прошли ли данные структурную проверку.
- `requires_review` — требуется ли дополнительная проверка.
- `errors` — обнаруженные ошибки.
- `warnings` — предупреждения.
- `extraction` — проверенные извлечённые данные.

Если данные некорректны или требуют дополнительной проверки, дальнейшая обработка может быть остановлена.

### 7. Формирование итоговой рекомендации

Для формирования итоговой рекомендации используется функция `generate_recommendation()`.

```python
from rag_module import search, generate_recommendation

answers = [
    {
        "question": "Что вас беспокоит?",
        "answer": "Болит поясница"
    },
    {
        "question": "Когда появилась боль?",
        "answer": "Три дня назад"
    },
    {
        "question": "Насколько сильная боль?",
        "answer": "Умеренная, примерно 5 из 10"
    }
]

search_results = search(
    question="Причины и возможные рекомендации при боли в пояснице",
    limit=5
)

recommendation = generate_recommendation(
    answers=answers,
    search_results=search_results
)

print(recommendation)
```

Функция получает ответы пользователя и найденные фрагменты медицинских документов, после чего формирует структурированную рекомендацию с помощью GigaChat.

Результат содержит следующие поля:

- `doctor` — рекомендуемый специалист.
- `urgency` — предполагаемая срочность обращения.
- `place` — рекомендуемое место обращения.
- `recommendation` — содержание рекомендации.
- `reason` — обоснование рекомендации.
- `evidence` — подтверждающие цитаты из найденных документов.

Допустимые значения `urgency`:

- `emergency` — экстренное обращение.
- `urgent_24h` — обращение в течение 24 часов.
- `planned` — плановое обращение.
- `self_care` — рекомендации по самопомощи.

Рекомендация формируется на основе переданных ответов и найденных документов. Цитаты проверяются на соответствие исходным фрагментам.

Если источники не содержат достаточной информации, формирование рекомендации может быть ограничено или остановлено.

### 8. Полный сценарий обработки пациента

Для последовательной обработки ответов пользователя предусмотрена функция `process_patient_answers()`.

```python
from rag_module import process_patient_answers

answers = [
    {
        "question": "Что вас беспокоит?",
        "answer": "Три дня насморк и першение в горле. Температуры нет, дышу нормально."
    },
    {
        "question": "Есть ли хронические заболевания или аллергии?",
        "answer": "Хронических заболеваний и известных аллергий нет."
    }
]

result = process_patient_answers(
    answers=answers,
    limit=5
)

print(result)
```

Функция объединяет основные этапы обработки:

1. Проверка ответов пользователя на наличие опасных признаков.
2. Остановка обработки при обнаружении опасного или неопределённого результата проверки безопасности.
3. Извлечение симптомов с помощью GigaChat.
4. Валидация извлечённых симптомов.
5. Проверка результата обработки симптомов.
6. Формирование поискового запроса на основе извлечённых данных.
7. Поиск релевантных медицинских фрагментов в Qdrant.
8. Формирование итоговой рекомендации с помощью GigaChat.

Таким образом, `process_patient_answers()` объединяет проверку безопасности, обработку ответов, поиск медицинской информации и генерацию рекомендации в одном сценарии.

Если на одном из этапов возникает ошибка или недостаточно данных, обработка может быть остановлена.

## Использование в Django

Установите библиотеку в окружение Django из её папки:

```
from rag_module import search, ask, index_document
```
пакет rag_module находится в backend рядом с приложением rag и импортируется напрямую.

Для индексации загруженного Django документа передавайте полный путь к файлу:

```python
from rag_module import index_document

index_document(absolute_path_to_file)
```

Для поиска информации:

```python
from rag_module import search

results = search("Поисковый запрос", limit=5)
```

Для генерации ответа:

```python
from rag_module import ask

result = ask("Пользовательский вопрос", limit=5)
```

Для генерации уточняющего вопроса:

```python
from rag_module import generate_next_question

result = generate_next_question(previous_answers)
```

Для полного сценария обработки ответов пользователя:

```python
from rag_module import process_patient_answers

result = process_patient_answers(
    answers=previous_answers,
    limit=5
)
```

Qdrant должен быть доступен из окружения, в котором работает Django.

Если Django и Qdrant запущены в Docker, необходимо использовать адрес Qdrant внутри соответствующей Docker-сети.

Важно: запуск приложения сам по себе не индексирует PDF. Каждый новый документ необходимо передать в `index_document()`.

## Структура библиотеки

- `__init__.py` — публичные функции библиотеки.
- `config.py` — настройки и переменные окружения.
- `database/` — подключение и работа с Qdrant.
- `document_loader/` — извлечение текста из PDF.
- `embeddings/` — создание векторных представлений текста.
- `processing/` — очистка, разбиение и индексация документов.
- `reranking/` — дополнительная оценка релевантности найденных фрагментов.
- `retrieval/` — поиск информации в Qdrant.
- `generation/` — генерация ответов, уточняющих вопросов и итоговых рекомендаций через GigaChat.
- `triage/` — проверка безопасности сообщений, извлечение и валидация симптомов, предварительная обработка результатов и управление сценарием опроса.
- `tests/` — автоматические и ручные тесты библиотеки.

## Примечания и ограничения

- Для корректной работы поиска необходимо предварительно проиндексировать подходящие документы.
- Качество ответов зависит от содержания и качества загруженных документов.
- Найденные фрагменты не гарантируют полноту медицинской информации.
- Генерация уточняющих вопросов не использует медицинскую базу документов.
- При отсутствии подтверждающей информации библиотека должна сообщать о её недостаточности, а не выдавать неподтверждённые утверждения.
- Проверка безопасности предназначена для предварительного выявления отдельных потенциально опасных признаков и не заменяет осмотр врача.
- Статус `no_critical_signs_detected` не подтверждает отсутствие заболевания или медицинского риска.
- Результаты GigaChat и автоматической обработки симптомов не являются клиническим диагнозом.
- Сгенерированные рекомендации требуют проверки квалифицированным медицинским специалистом и не должны использоваться как единственное основание для принятия медицинских решений.
