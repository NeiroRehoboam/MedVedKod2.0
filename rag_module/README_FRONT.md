# Получение ответов ИИ на Frontend
## 1. Откуда брать данные
Все итоговые ответы ИИ Frontend получает от Backend (Django) через API.
Источник данных — функция RAG Module:
```python
generate_recommendation(answers, search_results)
```
Backend самостоятельно:
1. Получает ответы пользователя на вопросы опроса.
2. Передаёт их в RAG Module.
3. Выполняет поиск подходящих фрагментов медицинских документов через Qdrant.
4. Передаёт найденные фрагменты и ответы пользователя в `generate_recommendation()`.
5. Получает результат от ИИ и отправляет его Frontend в формате JSON.

## 2. Формат ответа от Backend

Backend должен возвращать Frontend JSON следующего формата:

```json
{
  "doctor": "Терапевт",
  "urgency": "planned",
  "place": "Поликлиника",
  "recommendation": "Обратиться к специалисту для осмотра.",
  "reason": "Необходимо установить причину боли.",
  "evidence": [
    {
      "source": 1,
      "quote": "Цитата из медицинского документа.",
      "document": "Название документа",
      "page": 5
    }
  ]
}
```

## 3. Какие поля использовать на Frontend

| Поле JSON | Что отображать |
|---|---|
| `doctor` | Рекомендуемый специалист |
| `urgency` | Срочность обращения |
| `place` | Место обращения |
| `recommendation` | Итоговая рекомендация |
| `reason` | Объяснение рекомендации |
| `evidence` | Источники и подтверждающие цитаты |

### Обработка urgency

Поле `urgency` приходит в виде одного из четырёх значений. Frontend должен преобразовать его в понятный пользователю текст:

| Значение API | Текст на экране |
|---|---|
| `emergency` | Экстренное обращение |
| `urgent_24h` | Обратиться в течение 24 часов |
| `planned` | Плановое обращение |
| `self_care` | Самопомощь |

Не нужно самостоятельно определять срочность — Frontend только отображает значение, полученное от Backend.

## 4. Пример получения данных

Предположим, Backend предоставляет эндпоинт:

`GET /api/recommendations/{id}/`

Frontend получает JSON:

```javascript
const response = await fetch(`/api/recommendations/${id}/`);
const data = await response.json();

console.log(data.doctor);
console.log(data.urgency);
console.log(data.place);
console.log(data.recommendation);
console.log(data.reason);
console.log(data.evidence);
```

Пример преобразования срочности:

```javascript
const urgencyLabels = {
  emergency: "Экстренное обращение",
  urgent_24h: "Обратиться в течение 24 часов",
  planned: "Плановое обращение",
  self_care: "Самопомощь"
};

const urgencyText = urgencyLabels[data.urgency] ?? "Срочность не определена";
```

## 5. Отображение источников

Поле `evidence` содержит массив подтверждающих фрагментов.

Для каждого элемента Frontend может отображать:

- `document` — название медицинского документа;
- `page` — номер страницы;
- `quote` — цитату из документа.

Если массив `evidence` пустой, блок с источниками не отображается.

## 6. Важное для интеграции

- Все шесть полей итоговой рекомендации приходят от Django.
- Названия полей в JSON необходимо сохранять без изменений.
- Frontend не генерирует и не изменяет медицинские рекомендации.
- Конкретный URL API и HTTP-метод необходимо согласовать с Backend-разработчиком.
- Если Backend возвращает ошибку или рекомендация ещё формируется, Frontend должен корректно обработать это состояние.
