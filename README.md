# MedVedKod2.0

Медицинский помощник для первичной маршрутизации пациента на основе симптомов, анамнеза и клинических рекомендаций (RAG).

## 1. Настройка окружения

Скопируйте `.env.example` в `.env`:

```sh
cp .env.example .env
```

В PowerShell:

```powershell
Copy-Item .env.example .env
```

Обязательно задайте `SECRET_KEY` и `ENCRYPTION_PEPPER` — разные случайные значения, каждый генерируется командой `python -c "import secrets; print(secrets.token_urlsafe(64))"`. Без них backend не запустится.

Заполните необходимые переменные окружения. Для запуска без авторизации через MAX установите:

```dotenv
VITE_MOCK_AUTH=true
ENABLE_DEMO_LOGIN=True
```

Демо-вход подключается только при `DEBUG=True` и `ENABLE_DEMO_LOGIN=True`; в проде оставьте флаг выключенным — маршрут `/api/auth/demo/` тогда отсутствует.

## 2. Сборка и запуск

В корне репозитория выполните:

```sh
docker compose up --build -d
```

Миграции базы данных выполняются автоматически.

Для заполнения справочников тестовыми данными после миграций:

```sh
docker compose exec web python manage.py seed_dictionaries
```

При локальном запуске выполните из каталога `backend`:

```sh
python manage.py seed_dictionaries
```

Команда дополняет все справочники, включая справочники анамнеза. Повторный запуск не создаёт дубликаты и не изменяет существующие записи. Пациенты, анамнезы и сессии не создаются.

## 3. Индексация документов RAG

PDF-документы должны находиться в `backend/documents/`.

После запуска контейнеров выполните:

```sh
docker compose exec web python index_documents.py
```

При первом запуске загружается модель эмбеддингов, поэтому индексация может занять несколько минут.

## 4. Доступ к приложению

- Приложение: http://127.0.0.1:3000/
- Swagger: http://127.0.0.1:3000/api/docs/
- OpenAPI: http://127.0.0.1:3000/api/schema/

## Остановка

```sh
docker compose down
```

## Повторный запуск

```sh
docker compose up -d
```

Данные базы и проиндексированные документы сохраняются между запусками.
